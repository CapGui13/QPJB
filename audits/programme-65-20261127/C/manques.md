## 3. Contrôle ciblé réalisé

Test de cohérence exécuté en JavaScript sur les deux sources Git réelles, avant l’écriture : 1915 QCM / 1915 entrées de prérequis, correspondance exacte des IDs ; 25 fiches de dix références (250 occurrences, 203 IDs de référence distincts), 213 candidats distincts dans les groupes. Pour chacun des 229 IDs du réservoir de revue : existence dans les deux sources, main de 13 cartes, absence de doublon intra-couleur, distribution et H recalculés, réponse présente exactement une fois parmi les choix, énoncé/explication présents. Pour chaque référence et chaque candidat : minSession historique strictement inférieur à la séance humaine (index 0), concepts exigés introduits dans une séance antérieure selon PROGRAMME.md (ouv.position S30), concept du groupe concordant. Chaque référence est dans son groupe, dix IDs distincts par séance ; contraste obligatoire référencé ; repli non vide ; aucune nouvelle notion à S55–65. Résultat : PASS (aucune erreur détectée).

Limites : ce test n’est pas une simulation et ne prouve pas que le parcours d’un élève a effectivement atteint le nombre d’expositions requis. Les séances A/B doivent confirmer leurs expositions réelles. Le moteur doit vérifier chaque seuil, y compris les auto-prérequis, sur l’état enregistré. Les contrôles arithmétiques ne prouvent pas le SEF ni la qualité de tous les distracteurs ; les mains, enchères et raisons ont été examinées pour la sélection, mais les accords explicites et les lacunes ci-dessus restent à arbitrer. Les candidats conditionnels ne doivent jamais être promus en preuve de maîtrise simplement parce qu’ils sont présents dans ce fichier. Aucun test longitudinal, aucun test UI, aucune modification du moteur, aucune fusion.
